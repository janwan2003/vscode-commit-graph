Create a pull request from VS Code (GitHub, GitLab, Bitbucket)

A pull request (GitLab calls it a merge request) always needs two things: your branch has to be on the server, and someone has to fill in the form that asks for it to be merged. Git itself does neither of those for you in one step. This guide shows the quickest ways from a branch in VS Code to that form: a push, a URL, the command line, or an extension.

Step 1: push the branch

The forge can only offer a pull request for a branch it has. The first time you push a new branch, say where it goes and ask git to remember it:

git push -u origin feature/login
To github.com:you/app.git
 * [new branch]      feature/login -> feature/login
branch 'feature/login' set up to track 'origin/feature/login'.

-u (long form --set-upstream) makes origin/feature/login the branch’s upstream: the remote branch it tracks. After that, a plain git push or git pull knows where to go, and VS Code’s status bar shows how many commits you are ahead or behind. git push -u origin HEAD does the same for whatever branch you are on, without typing its name.

Without an upstream, a plain git push stops with:

fatal: The current branch feature/login has no upstream branch.
To push the current branch and set the remote as upstream, use

    git push --set-upstream origin feature/login

To have git set the upstream on the first push automatically, run git config --global push.autoSetupRemote true. In VS Code, Publish Branch… in the Source Control view does the same for a branch with no upstream.

Step 2: open the new pull request page

Each forge has a web address that opens its “new pull request” form with your branch already filled in. You choose the target branch, title and description there. Replace the parts in angle brackets; branch names with slashes, like feature/login, work as they are.

GitHub

https://github.com/<owner>/<repo>/compare/<branch>?expand=1
https://github.com/<owner>/<repo>/compare/<base>...<branch>?expand=1

The first form compares your branch with the repository’s default branch. The second names the base, for example compare/release...feature/login. expand=1 shows the pull request form straight away instead of only the diff. GitHub’s documentation on query parameters for pull requests describes the base...branch form with quick_pull=1, which also accepts title and body. For GitHub Enterprise, use your server’s address instead of github.com.

GitLab

https://gitlab.com/<group>/<project>/-/merge_requests/new?merge_request[source_branch]=<branch>

This is the link GitLab itself prints after you push a new branch (“To create a merge request for …, visit:”), with the square brackets encoded as %5B and %5D; see GitLab’s merge guide. You pick the target branch on the form. For a self-managed GitLab, use its address. GitLab can also open the merge request during the push: git push -o merge_request.create (with -o merge_request.target=<branch> to set the target), per its push options page.

Bitbucket Cloud

https://bitbucket.org/<workspace>/<repo>/pull-requests/new?source=<branch>

This address is widely used, but as of November 2026 we could not find it in Atlassian’s public documentation, so treat it as a convenience: check that the form shows the right source branch before you submit. Atlassian’s documented route is Create → Pull request in the repository, or the create button on the branch’s page. Bitbucket Data Center (self-hosted) uses different addresses.

All three pages need you to be signed in to the forge in your browser, which you usually are already.

From the command line

GitHub’s CLI, gh, creates the pull request without a browser once you have run gh auth login:

gh pr create --fill                 # title and body from your commits
gh pr create --base release --draft
gh pr create --web                  # open the form in the browser instead

If the branch is not fully pushed yet, gh asks where to push it (its help text says so). GitLab’s equivalent is glab mr create.

With a forge extension

Both big forges publish their own VS Code extension, and they do much more than open a form:

  • GitHub Pull Requests (by GitHub) adds a GitHub Pull Requests: Create Pull Request command, according to VS Code’s GitHub documentation. It also lists pull requests and issues, checks pull requests out, and lets you review them with comments in the editor. You sign in to GitHub first.
  • GitLab for VS Code (by GitLab, marketplace ID GitLab.gitlab-workflow) lets you review and discuss merge requests, see pipelines and browse issues. You connect it to GitLab with OAuth or a personal access token, per GitLab’s setup guide.

If you review code every day, one of these is worth installing. If you only want to get from a branch to the form, a URL is lighter: no sign-in inside the editor and no token to manage.

Do it in Mergeline

Mergeline is a free, MIT-licensed git graph for VS Code. From version 0.8 it can open the new pull request page for any branch you can see in the graph.

  1. Right-click a branch badge, either a local branch that tracks a remote branch or a remote branch itself, and choose Create pull request on GitHub (or GitLab, or Bitbucket, depending on where the remote is).
  2. Your browser opens the forge’s form for that branch, using the URLs above. For a local branch, Mergeline uses the name of the remote branch it tracks. The forge picks the target branch, and you can change it on the form.
  3. Not pushed yet? Mergeline tells you and offers to push the branch first. You can also right-click the branch and choose Push, which sets the upstream like git push -u.

Mergeline only builds the address from your remote’s URL and hands it to your browser. It makes no network request of its own (apart from a push you ask for) and needs no sign-in or token. It recognises github.com, gitlab.com and bitbucket.org, plus self-hosted servers whose host name contains “github” or “gitlab”.
