A maintained alternative to the Git Graph extension

Git Graph is one of the best-known extensions for VS Code. It made a clickable commit graph inside the editor something many developers now expect, and plenty of people still use it every day. This page is for those who want a graph extension that is actively released and that anyone may fork. It sets out the facts, shows the plain git commands behind each graph action (useful whichever tool you choose), and explains how to try Mergeline alongside what you have.

Mergeline is an independent project. It is not affiliated with or endorsed by Git Graph or its author, and it contains no Git Graph code: it was written from scratch, from git’s own documented behaviour.

What the licence difference means in practice

When an extension’s licence does not allow derivative works to be published, people who want to fix something in it cannot release their own patched copy for others to install. Changes can only arrive through new official releases. That is a legitimate choice for an author to make, and it is the reason Mergeline is a separate, clean-room implementation rather than a fork.

Mergeline’s MIT licence makes the opposite choice. Anyone may fork it, fix it and publish their version. If Mergeline’s own development ever stopped, the community could carry it on without asking permission. (This is a plain-language summary, not legal advice; read each licence yourself if it matters to you.)

Do you need to switch?

Not necessarily. If your current setup does everything you need in the editor you use, there is no urgency. People tend to look for an alternative when they want releases that keep pace with new editor versions, when they work in VSCodium or Cursor and want one tool everywhere, or when they want the option to fork. Both extensions can be installed at the same time, so you can compare them on your own repositories before deciding.

The git behind every graph action

A graph extension is a friendly front end to ordinary git commands. Knowing them makes any graph tool less mysterious, and lets you do the same thing in a terminal or a script:

In the graphIn the terminal
See every branchgit log --graph --oneline --all
Check out a remote branch as a local onegit switch feature (creates feature tracking origin/feature)
Create a branch at a commitgit branch fix-login 72c5f10
Tag a commit (lightweight / annotated)git tag v1.2.0 72c5f10 / git tag -a v1.2.0 -m "Release 1.2.0" 72c5f10
Push a taggit push origin v1.2.0
Merge a branch into the current onegit merge feature
Rebase the current branch onto anothergit rebase main
Cherry-pick / revert a commitgit cherry-pick 4e7d0c2 / git revert 4e7d0c2
Reset the current branch to a commitgit reset --soft, --mixed or --hard 72c5f10
Rename a branchgit branch -m old-name new-name
Delete a branchgit branch -d feature (-D to force)
Delete a branch or tag on the remotegit push origin --delete feature
Files changed between two commitsgit diff --stat 3a9b6d4 9f2c1ab
Apply, pop, drop a stash, or branch from itgit stash apply, pop, drop, git stash branch name

There are guides on this site for the trickier ones: rebase vs merge, reset, revert, cherry-pick and the reflog, and stash.

What Mergeline covers

  • Graph: coloured lanes, merges, badges for local and remote branches, tags and HEAD, stashes as nodes, and a row for uncommitted changes.
  • Table: graph, description, date, author and hash columns with a fixed header. Virtualised rows and incremental loading for repositories with 100,000 commits.
  • Details and compare: full message, author, committer, parents and changed files with line counts; files open in the editor’s diff view. Ctrl/Cmd-click two commits to compare them.
  • Find and filter: search subject, author, hash and ref names; filter by branch; toggle remotes.
  • Actions: everything in the table above, plus an interactive rebase in the terminal and copying hashes, subjects and names.
  • Repositories: multi-root workspaces, nested repositories and worktrees, local or remote (SSH, WSL).

Try it in Mergeline

  1. Install the .vsix from the latest release with Extensions: Install from VSIX…. Your existing extensions are not touched; Mergeline’s commands and settings all start with mergeline.
  2. Open the graph with the Mergeline button in the Source Control title bar, the status-bar button, or Mergeline: Show Commit Graph.
  3. Give it a keyboard shortcut if you like. Run Preferences: Open Keyboard Shortcuts (JSON) and add: 
    { "key": "ctrl+alt+g", "command": "mergeline.show" }
    Pick any free key combination.
  4. Adjust the settings under mergeline. in the Settings editor: how many commits load first, remote branches, stashes, the uncommitted row, the status-bar button, and the date format (relative, ISO or locale).
  5. Compare on your own repositories. If you settle on Mergeline, disable the other extension from the Extensions view (globally or just for one workspace). Found something missing? Open an issue.
