Your whole repository as one graph, with the git actions where you need them

Mergeline draws every branch, merge, tag and stash of your repository as an interactive commit graph inside VS Code, VSCodium, Cursor and Windsurf. Right-click a commit or a branch to check it out, merge it, rebase onto it, cherry-pick it, revert it or reset to it. Click a commit to see what changed and open any file in the editor’s own diff view. There is no account, no paid tier and no telemetry.

Features

Items marked not built in are not available in VS Code’s built-in Source Control Graph (compared with VS Code 1.147).

A real graph

Coloured lanes for every branch, merge lines, and badges for local branches, remote branches, tags and HEAD. Stashes appear as their own nodes not built in, and a row at the top shows uncommitted changes not built in.

A readable table not built in

Columns for graph, description, date, author and short hash, under a header that stays put while you scroll. Drag a column edge to resize it and right-click the header to hide columns; the layout is remembered. Dates can be relative, ISO or in your locale’s format.

Built for big repositories

Only the rows on screen are drawn. Mergeline loads the first 500 commits (configurable) and fetches more as you scroll, so it stays responsive on repositories with 100,000 commits.

Commit details not built in

The full message, author and committer, parents, and every changed file with lines added and removed, in a folder tree or as a flat list. Click a file to open it in the editor’s own diff view; right-click it to open it as it was at that commit, compare it with your working copy or show its history. Links and #123 issue numbers in messages are clickable, with an Open on GitHub link (GitLab and Bitbucket too).

File history

Right-click any file in the Explorer, an editor tab or the editor and choose Show File History in Mergeline. The graph shows only the commits that touched it, still connected, with the file highlighted in each commit’s details. Renamed and moved files are followed back through their old names.

Commit order: date or topology

Sort by commit date, author date or topology from the toolbar or the mergeline.commitOrder setting. Topology order keeps each branch’s commits together, which means fewer crossing lines on busy repositories.

Compare any two commits not built in

Ctrl-click (Cmd-click on macOS) a second commit to list every file that differs between the two, and open each diff. Or right-click a commit for Compare with working tree, or a branch to compare it with the current one, or to see only what it changed since it split off (what a merge would bring in).

Edit history from the graph not built in

Right-click a commit on your branch to edit its message (subject and body), move it up or down, squash it into its parent or drop it, or Ctrl/Cmd-click a second commit to squash the range into one. No editor or terminal opens, uncommitted changes are stashed and restored, pushed commits get a warning first, and every change has an Undo. See it.

main and develop stay straight new in 0.14

Pinned branches keep their own column on the left with a fixed colour, so main, master and develop are always one straight line instead of moving between columns as other branches come and go. A git-flow history reads at a glance: main on the far left, develop next to it, features and releases to the right. Right-click any branch to pin or unpin it, or list names and patterns like release/* in mergeline.pinnedBranches. See it · without pinning · Git flow guide.

Bisect from the graph 0.13

Find the commit that broke something without leaving VS Code. Right-click a commit and choose Start bisect: this commit is bad, mark one that still worked, and press Good or Bad in the bar for each commit git checks out. The bar counts what is left (“4 commits left, about 3 steps”), the graph marks every commit you judged, and Run a test command… lets git bisect run do the rest. See it · Git bisect guide.

Ahead/behind, update without checkout, signatures

Branch badges show ↑2 commits to push and ↓3 to pull, and ✕ when the upstream was deleted. Right-click a branch you are not on and choose Update from origin/… (fast-forward) to bring it up to date without switching, or right-click a remote branch to fetch and merge it into yours in one step. Tick First parent in the toolbar to read a mainline one merge at a time, and see each commit’s GPG or SSH signature status in its details. See it · Ahead/behind guide · Update without checkout · First parent guide · Signed commits guide.

Find by path, issue links, archives 0.11

Type path:src/auth or path:*.md in Find to step through every commit in history that changed a matching file or folder. Turn Jira, Linear or any tracker’s keys in commit messages into links with mergeline.issueLinks. Right-click a commit, branch or tag to save it as a zip or tar.gz. Tags show their tagger and message in the details, and author avatars are an opt-in setting. See it · Path search guide · Issue links guide · Archive guide.

Fixup commits, conflicted files 0.10

Right-click a commit on your branch and choose Create fixup commit for this to turn your staged changes into a fixup! commit, then Squash fixup commits into their targets folds them all in with one autosquash rebase, no editor. A stopped rebase or merge now lists its conflicted files in the bar; click one to open the merge editor. Fixup guide · Merge conflicts guide.

Review file by file, manage remotes 0.9

Click Review on a commit, a comparison or a branch’s changes to get a check mark per file, an N of M reviewed count and a Next unreviewed button; progress survives a restart. Remotes… lists your remotes to add, fetch and prune, change a URL, rename or remove. Review guide · Remotes guide.

Drag a commit new in 0.8

Drag a commit from another branch onto your current branch to cherry-pick it. Drag a commit on your branch onto another one to squash it into that commit or move it right after it. Branch menus also gain Create pull request on GitHub (GitLab, Bitbucket). Cherry-pick guide · Pull request guide.

Stopped rebase? The graph says so

When a rebase, merge, cherry-pick or revert stops on a conflict, from the graph or from a terminal, a bar above the graph shows the step, the commit it stopped at and the conflicted files, with Continue, Skip, Abort and Source Control. Continue never opens an editor. Guide.

Drag and drop branches

Drag a branch badge onto another branch or any commit, then pick: merge it there, rebase it onto it, move the branch to that commit, or compare the two. Nothing runs until you choose from the menu, and rebases and moves ask first. See it.

Worktrees

Every other worktree of the repository shows as a badge on the commit it has checked out. Check a branch out into a new worktree, open a worktree in a new window or remove it, all from the graph. More in the git worktree guide.

Find not built in

Search subjects, authors, hashes and branch or tag names, and step through matches with next and previous. All history searches commits that are not loaded yet, and path: finds the commits that changed a file or folder.

Filter by branch new in 0.8

Tick any set of local or remote branches to see only their history, or just the current branch. Hide remote-tracking branches with one toggle, or dim every commit that is not in your branch’s history. See it · Guide.

Commit actions

Checkout, create a branch, add a lightweight or annotated tag, cherry-pick, copy the hash or subject. Plus not built in: revert, merge into the current branch, rebase the current branch onto it, reset soft, mixed or hard, and an interactive rebase in the terminal.

Branch actions

Checkout (a remote branch becomes a local tracking branch), delete (with a force option if unmerged), copy the name. Plus not built in: merge, rebase onto, rename, push, and delete the branch on the remote.

Tags and stashes not built in

Push a tag, delete it locally and on the remote. Apply, pop or drop a stash, or turn it into a new branch.

Every repository you have open

A repository picker covers multi-root workspaces, nested repositories and worktrees. The toolbar has the picker, the branch filter, the Remote branches toggle, the remotes list, find, fetch and refresh.

Careful by default

Actions that rewrite or delete something, such as a hard reset, a rebase or deleting a remote branch, ask first in a modal dialog. Push and fetch go through VS Code’s git extension when it is available, so your usual credential prompts work.

Why another git graph?

VS Code ships a basic history graph, and there are older graph extensions that many people still use. Mergeline exists because a tool you use every day should be one you can count on next year too.

Maintained

Mergeline is new (first release November 2026) and under active development. Bugs and requests go to a public issue tracker on GitHub, next to the code.

MIT, so you can fork it

The licence lets anyone fork, fix and republish the code. If this project ever stops, the community can carry it on without asking anyone’s permission. Read more in a maintained alternative to Git Graph.

Free, nothing paywalled

Every feature on this page is free. There is no Pro tier, no trial, no sign-in and no upsell inside the graph.

For every VS Code-based editor

Mergeline is being published on Open VSX, the registry VSCodium, Cursor and Windsurf search, as well as the VS Code Marketplace. Both listings are coming soon; the .vsix works in all of them today.

Install

  1. Download mergeline-0.14.0.vsix from the latest GitHub release.
  2. Install it. In VS Code, VSCodium, Cursor or Windsurf open the Command Palette (Ctrl+Shift+P, or Cmd+Shift+P on macOS), run Extensions: Install from VSIX… and choose the file. From a terminal you can instead run one of: 
    code --install-extension mergeline-0.14.0.vsix
codium --install-extension mergeline-0.14.0.vsix
cursor --install-extension mergeline-0.14.0.vsix
  3. Open a folder that is a git repository and trust it when the editor asks (Mergeline runs git commands, so it is disabled in Restricted Mode). Then open the graph in any of three ways: the Mergeline button in the Source Control view’s title bar, the Mergeline button in the status bar, or the command Mergeline: Show Commit Graph.

Requires VS Code 1.85 or newer (or an editor built on it) and git installed on your machine. Mergeline also works in remote windows such as Remote SSH and WSL; git has to be installed on the remote side.

FAQ

Is it really free?

Yes. Mergeline is open source under the MIT licence. Every feature is free, with no paid tier, no account and no ads.

Does it send anything anywhere?

No. Mergeline has no telemetry, and with the default settings it makes no network requests of its own. It runs git on your machine. The only network traffic it causes is the fetches and pushes you ask for, which go to your own remotes, and, only if you turn on the mergeline.showAvatars setting (off by default), author pictures that VS Code loads from GitHub or Gravatar. See the privacy policy.

How is it different from the graph built into VS Code?

VS Code’s Source Control Graph is good for a quick look at recent history. Mergeline adds a table with author, date and hash columns, a details pane with per-file diffs, comparing two commits, search, a branch filter, stashes and uncommitted changes in the graph, and the actions the built-in graph does not have: merge, rebase, revert, reset, rename, push, and deleting branches and tags on the remote. The branch graph guide compares the two.

Does it work in VSCodium, Cursor and Windsurf?

It is built for them: they run VS Code extensions and install the same .vsix, Mergeline uses only standard VS Code APIs, and its right-click menus are drawn by Mergeline itself inside its panel. (That also means an editor bug in webview menus, like VS Code’s in early 2025, could affect it; we would ship a fix.) Our end-to-end tests pass in VS Code 1.147 and VSCodium 1.143; Cursor and Windsurf are not tested yet. If something misbehaves in a fork, please open an issue. See Git graph in Cursor and VSCodium.

Can it break my repository?

Mergeline runs ordinary git commands, the same ones you would type, and asks before each one. Destructive actions such as a hard reset, a forced branch delete or deleting a remote branch use a modal confirmation. Most mistakes can still be undone with the reflog; see the undo guide.

My repository is huge. Will it cope?

It draws only the rows you can see and loads commits in batches, starting with 500. If the first load is still slow, lower the mergeline.initialCommits setting (minimum 50). More tips are on the support page.

Can I use it alongside Git Graph or GitLens?

Yes. Mergeline uses its own commands and settings (all under mergeline.), so it can be installed next to other git extensions. It is an independent project and is not affiliated with either of them.
