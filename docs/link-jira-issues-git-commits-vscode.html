Link Jira issues in git commits: clickable issue keys in VS Code

Many teams put the issue key in every commit message: PROJ-123 Fix login retry. Git treats that as plain text. It does not know what Jira is, so the key only becomes useful when something turns it back into a link. This guide covers how to write keys so they are easy to find, a hook that adds them for you, how to search history by key with plain git, and how to make the keys clickable in VS Code with one setting in Mergeline.

Where to put the key

There are two common habits, and either works:

  • In the subject: PROJ-12 Fix login retry. Visible in every one-line log and in the graph, at the cost of a few characters of the subject.
  • As a trailer at the end of the message, after a blank line: Refs: PROJ-14. A trailer is a Key: value line in the last paragraph of a message; git can add and read them. Subjects stay short, and tools can pick the value out reliably.
git commit -m "Fix crash" -m "Longer body." --trailer "Refs: PROJ-14"
git log -1 --format=%B
Fix crash

Longer body.

Refs: PROJ-14
git log -1 --format='%(trailers:key=Refs,valueonly)'
PROJ-14

Whichever you choose, write the key exactly as your tracker does, in capitals with the hyphen: a link pattern that expects PROJ-12 will not match proj 12.

Add the key from the branch name

If your branches are named after issues, such as feature/PROJ-42-login, a prepare-commit-msg hook can add the trailer so nobody has to remember. Save this as .git/hooks/prepare-commit-msg and make it executable (chmod +x):

#!/bin/sh
# Add "Refs: ABC-123" when the branch name contains an issue key.
case "$2" in ""|message) ;; *) exit 0 ;; esac
key=$(git branch --show-current | grep -oE '[A-Z][A-Z0-9]+-[0-9]+' | head -n 1)
[ -n "$key" ] || exit 0
grep -q "$key" "$1" || git interpret-trailers --in-place --trailer "Refs: $key" "$1"

In our test on feature/PROJ-42-login, git commit -m "Tidy login form" produced a message ending in Refs: PROJ-42; a message that already contained PROJ-42 was left alone, and on main nothing was added. The case line skips merges, squashes and -c/-C reuse, where the message comes from elsewhere. Hooks are local to your clone and are not pushed, so each teammate installs it (or your team shares it through core.hooksPath).

Find commits by issue key

git log --oneline --grep='PROJ-13'
daf588a PROJ-13 Fix login retry
git log --oneline -E --grep='PROJ-[0-9]+'
daf588a PROJ-13 Fix login retry
c85a64a PROJ-12 Initial commit
git log --oneline -i --grep='proj-12'      # ignore case
c85a64a PROJ-12 Initial commit

--grep searches the whole message, subject, body and trailers. Add --all to look in every branch rather than only the current one. Watch out for prefixes: in our test --grep='PROJ-1' returned four commits, including PROJ-12 and PROJ-13. -E --grep='PROJ-1([^0-9]|$)' returned only the one for PROJ-1.

Write the pattern

To turn keys into links, a tool needs a regular expression that finds them and a URL to send each one to. The usual Jira-style pattern is “capital letters, a hyphen, digits”. We ran it with JavaScript’s RegExp over a sample message:

\b[A-Z][A-Z0-9]+-\d+\b  on  "Fix PROJ-12 and AB2-7; see utf-8 and ISO-8601 and SHA-256"
PROJ-12, AB2-7, ISO-8601, SHA-256

It works, but it also matched ISO-8601 and SHA-256, which are not issues. If that happens in your messages, list your real project keys instead: \b(?:PROJ|OPS)-\d+\b. Capture groups let you reuse part of a match: with \bAB#(\d+)\b on Fixes AB#1234, group 1 is 1234, which is what an Azure Boards work-item URL needs.

For the URL, open one issue in your browser and look at its address; replace the key with the placeholder. Common shapes (check yours, since sites and workspaces differ):

  • Jira Cloud: https://yourcompany.atlassian.net/browse/PROJ-12
  • Linear: https://linear.app/yourteam/issue/ENG-91
  • YouTrack: https://youtrack.example.com/issue/PROJ-12
  • Azure Boards: https://dev.azure.com/yourorg/yourproject/_workitems/edit/1234

Clickable keys in Mergeline

Mergeline is a free, MIT-licensed git graph for VS Code. From version 0.11 it can turn any pattern in a commit message into a link.

  1. Open your settings JSON (Preferences: Open User Settings (JSON) in the Command Palette).
  2. Add mergeline.issueLinks, a list of objects with a pattern (a JavaScript regular expression) and a url. In the URL, $0 is the whole match and $1, $2 … are capture groups. In JSON every backslash is written twice: 
    "mergeline.issueLinks": [
  { "pattern": "\\b[A-Z][A-Z0-9]+-\\d+\\b", "url": "https://yourcompany.atlassian.net/browse/$0" },
  { "pattern": "\\bAB#(\\d+)\\b", "url": "https://dev.azure.com/yourorg/yourproject/_workitems/edit/$1" }
]
  3. Click a commit. In the details pane, every match in the subject and body is a link; clicking it opens the issue in your browser.

GitHub, GitLab and Bitbucket #123 references keep working without any setting: Mergeline builds those links from the remote’s URL. Nothing is fetched for either kind of link.

What it does not do: it does not contact Jira or any other tracker, so it cannot show an issue’s title or status, check that the issue exists, or sign you in. A key that matches your pattern becomes a link whether or not that issue is real, which is why a narrow pattern is worth the effort. It also does not change your commits; the messages stay as they are.

FAQ

Does this work with self-hosted Jira (Data Center)?

Yes, as long as your browser can open the URL. Only the URL template changes, for example https://jira.example.com/browse/$0. Mergeline never connects to it; your browser does, with your usual sign-in.

Can I have several trackers at once?

Yes. mergeline.issueLinks is a list, so add one entry per tracker, each with its own pattern and URL, as in the example above.

Why is my pattern not matching?

Usually a single backslash in the JSON: "\b" in JSON is a backspace character, not a word boundary. Write "\\b" and "\\d". Mergeline also shows a warning naming any entry it skipped, for example a url that does not start with http:// or https://, or a pattern that is not a valid regular expression. Test the pattern on a real message first, for example in your browser’s developer console with "PROJ-12 fix".match(/\b[A-Z][A-Z0-9]+-\d+\b/g).

Do the links show in a plain git log?

No. Git prints the message as text. VS Code’s terminal makes full https:// addresses clickable, so a trailer such as Refs: https://yourcompany.atlassian.net/browse/PROJ-14 is clickable there, but a bare key is not.
