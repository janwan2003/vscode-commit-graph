How to see a git branch graph in VS Code

A list of commits tells you what happened. A graph tells you where: which branch a commit is on, where a feature split off, whether it has been merged, and how far your branch is behind main. VS Code gives you three ways to get that picture. This guide covers each one, with the commands and flags worth knowing, so you can pick the right tool for the question you are asking.

1. git log --graph in the integrated terminal

Git can draw a text graph itself. Open the integrated terminal (Ctrl+`) and run:

git log --graph --oneline --decorate --all

Each flag does one job: --graph draws the lines, --oneline shows a short hash and the subject, --decorate prints branch and tag names next to their commits (modern git does this by default in a terminal), and --all includes every branch, remote-tracking branch and tag instead of just the one you are on. The output looks like this:

*   9f2c1ab (HEAD -> main, origin/main) Merge branch 'feature/search'
|\
| * 4e7d0c2 (feature/search) Highlight matches in results
| * b18a9e3 Add search box to toolbar
* | 72c5f10 Fix date parsing in log view
|/
* 3a9b6d4 (tag: v0.3.0) Release 0.3.0
* 0c1e8f7 Initial commit

Flags that make it more useful

  • -n 30 limits output to the 30 newest commits. Longer output opens in a pager; press q to leave it.
  • --branches or --remotes instead of --all show only local or only remote-tracking branches.
  • --simplify-by-decoration hides every commit that has no branch or tag on it. On a busy repository this shrinks the graph to its skeleton: where branches start and end.
  • --first-parent follows only the first parent of each merge. On main this shows one line per merged pull request rather than every commit inside it.
  • main..feature shows commits on feature that are not on main yet, which is exactly what a merge would bring in.
  • --since="2 weeks ago", --author="Sam" and --grep="search" filter by date, author and message. -S"parseDate" finds commits that added or removed that exact string.

A custom format adds the author and a relative date. Save it as an alias so you never type it again:

git config --global alias.lg "log --graph --all --format='%C(auto)%h%d %s %C(dim)%an, %ar'"
git lg -n 40

Before reading any graph, run git fetch --all --prune. Remote-tracking branches such as origin/main only move when you fetch, and --prune removes ones deleted on the server. A graph drawn from stale refs answers the wrong question confidently.

Reading the graph

  • Each * (or dot, in a graphical tool) is a commit. Newest is at the top.
  • A vertical line is a line of development. Lines that split going up are branches being created; lines that join going up are merges.
  • A merge commit has two parents. The first parent is the branch you were on when you merged; the second is the branch you merged in.
  • A branch name is just a label on one commit. In the example above, feature/search is still pointing at 4e7d0c2 even though that work is already merged into main, so it is safe to delete with git branch -d feature/search.

The terminal graph is always available, scriptable and exact. Its limits show up quickly, though: you cannot click a commit to see its diff, long histories scroll off screen, and acting on what you see means copying hashes into more commands.

2. The built-in Source Control Graph

Recent versions of VS Code include a graph in the Source Control view (Ctrl+Shift+G). It shows the history of your current branch alongside its upstream, with incoming and outgoing commits marked, and you can choose which other branches to include. Clicking a commit opens its changes.

It also has a right-click menu. In VS Code 1.147, a commit can be checked out (as a detached HEAD), used to create a branch or a tag, cherry-picked, compared, or have its hash or message copied. Branch and tag labels can be checked out or deleted. (We read this list from the menus defined in VS Code’s bundled git extension.)

That covers a quick look at recent history very well, and it needs nothing installed. What it does not have is a table with author, date and hash columns, a details pane, comparing two arbitrary commits, search, stashes in the graph, or actions such as merge, rebase, revert and reset.

3. A graph extension

When the graph is where you work rather than something you glance at, an extension gives you the whole repository at once: every branch in coloured lanes, who changed what and when, and the git operations on a right-click. That is the gap Mergeline is built for.

Do it in Mergeline

  1. Install the .vsix from the latest release with Extensions: Install from VSIX… (full steps).
  2. Open the graph with the Mergeline button in the Source Control title bar, the status-bar button, or Mergeline: Show Commit Graph.
  3. Fetch first. Click Fetch in the toolbar so origin/* branches are current.
  4. Narrow it down. Use the branch filter to follow one branch, or the Remote branches checkbox to hide remote-tracking branches. This is the graphical version of --branches and --all.
  5. Inspect. Click a commit to open its details: message, author, committer, parents, and each changed file with its line counts. Click a file to open the diff. Ctrl-click (Cmd-click on macOS) a second commit to compare the two; the compare guide explains which commits to pick and the matching git diff commands.
