Download a git commit, branch or tag as a zip with git archive

Sometimes you need the files of a project as they were at one point, without the history: a release to hand to a customer, a snapshot to attach to a ticket, or an old version to unpack next to the current one. Zipping your project folder is the wrong tool, because it picks up .git, build output, node_modules, .env files and whatever you have not committed. git archive packs exactly what a commit contains. This guide covers the command, its useful options, what is and is not included, and how to do it from the graph in VS Code.

We ran every command on this page with git 2.53 in throwaway repositories and quote the output we saw.

Zip a commit, branch or tag

git archive --format=zip -o /tmp/out.zip HEAD
git archive -o /tmp/out.tar.gz v1.0       # format taken from the file name
git archive -o /tmp/out.tar main
git archive --list
tar
tgz
tar.gz
zip

The last argument is what to pack: a branch, a remote branch such as origin/main, a tag, a hash, or an expression like HEAD~3. With -o, git picks the format from the file extension: in our test out.zip came out as a zip archive, out.tar.gz and .tgz as gzip-compressed tar, and .tar as plain tar. --format=zip sets it explicitly. Without -o, git writes a tar archive to standard output, which is handy for piping: git archive HEAD | tar -x -C /tmp/snapshot.

Zip opens anywhere with a double-click, including Windows; .tar.gz is the norm for Linux and source releases and is usually smaller. For zip, -9 asks for the best compression.

What is in the archive

Only the files git tracks, exactly as they are in that commit. In our test repository, which also had an untracked notes.txt, an ignored .env and an ignored node_modules/, the zip of HEAD listed:

.gitignore
README.md
docs/
docs/guide.md
package.json
src/
src/auth/
src/auth/login.ts
  • No .git folder, so no history; the receiver gets files, not a repository.
  • No untracked or ignored files, even if they are on your disk.
  • No uncommitted changes. We edited README.md without committing; the archive of HEAD still had the committed text. Commit first if you want your edits in.
  • Submodules are empty folders. A submodule at lib/sub appeared only as lib/sub/, with nothing inside.
  • File dates are the commit date, not today. After a commit made with a 2024 date, every file in the archive was dated 2024-03-05.
  • The commit is recorded. For a tar archive, git get-tar-commit-id printed the full hash of the commit it was made from, and a zip carries the same hash as its archive comment (unzip -l shows it on the second line).

Leave files out: export-ignore

Tests, CI configuration and other files your users do not need can be kept out of every archive with a line in .gitattributes:

tests/          export-ignore
.gitattributes  export-ignore

After committing that, the archive of the commit no longer had tests/ or .gitattributes. Git reads the .gitattributes of the commit being archived: when we added docs/ export-ignore without committing it, docs/ was still included. --worktree-attributes makes git use your working copy’s attributes instead; with it, docs/ was left out. Archiving an old tag therefore follows the rules that were in place at that tag.

A top folder, one subfolder

git archive --prefix=myapp-1.0/ -o myapp-1.0.tar.gz v1.0
myapp-1.0/
myapp-1.0/README.md
myapp-1.0/src/auth/login.ts  …
git archive -o src.zip HEAD src/          # keeps the src/ folder
git archive HEAD:src | tar -t              # contents of src/ at the top
auth/
auth/login.ts

--prefix puts every path under one folder, so unpacking does not spill files into the current directory. Keep the trailing slash; without it the prefix is glued to each file name. Paths after the commit limit the archive to those files or folders. HEAD:src archives the folder’s contents with src/ itself removed from the paths.

Save as archive in Mergeline

Mergeline is a free, MIT-licensed git graph for VS Code. From version 0.11 you can save any point in the graph as an archive without typing a ref.

  1. Right-click a commit, a branch badge (local or remote) or a tag, and choose Save as archive (zip, tar.gz)…
  2. Choose where and which format in the save dialog: .zip, .tar.gz or .tar.
  3. Mergeline runs git archive on that commit and writes the file. Everything goes inside one top folder named after the file, so app-v1.0.zip unpacks into app-v1.0/, as with --prefix above.

The archive follows the rules above: the tracked files at that commit only, no .git folder, no untracked or ignored files, and paths marked export-ignore in .gitattributes are left out. To archive a single subfolder, or to use --worktree-attributes, run the command in the terminal.

FAQ

Is this the same as “Download ZIP” on GitHub or GitLab?

The result is similar, but the web button only works for commits that are pushed, and it downloads from the server. git archive runs on your machine and works for any commit you have, including local branches nobody else has seen.

Can I get just the files that changed in one commit?

Not with a plain git archive, which always packs whole trees. You can pass it the changed paths: git archive -o changed.zip HEAD $(git diff --name-only HEAD~1 HEAD). That fails if the commit deleted a file, because the path no longer exists in HEAD, and file names with spaces need more care.

How do I unpack an old version next to my project?

mkdir /tmp/v1 && git archive v1.0 | tar -x -C /tmp/v1. If you want to build and work in it with git, a worktree is usually better, since it keeps the history.
