Troubleshooting

“git: command not found”, or the graph stays empty

Mergeline needs git installed on the machine where your files are. Open a terminal inside the editor and run:

git --version

If that fails, git is missing or not on the PATH the editor sees:

  • Windows: install Git for Windows from git-scm.com and keep the installer option that adds git to PATH.
  • macOS: run xcode-select --install for Apple’s command line tools, or install git with Homebrew (brew install git).
  • Linux: install it with your package manager, for example sudo apt install git or sudo dnf install git.

Then quit the editor completely and start it again. The editor reads PATH when it starts, so a new install is not visible to a window that was already open. On macOS, an editor launched from the Dock may not see PATH changes made only in your shell profile; launching it once from a terminal (code .) is a quick way to check whether that is the cause.

In a remote window (Remote SSH, WSL, containers) Mergeline runs on the remote side, so git must be installed there, not only on your local computer.

Mergeline is disabled, or says the workspace is not trusted

Mergeline runs git commands in your workspace, and git can run hooks and other programs configured in a repository. For that reason it does not run in Restricted Mode, the mode VS Code uses for folders you have not trusted yet. To grant trust:

  1. Open the Command Palette and run Workspaces: Manage Workspace Trust.
  2. Choose Trust (or trust the parent folder if you keep many repositories in one place).

Only trust folders whose contents you are comfortable running. If the Mergeline buttons do not appear after you grant trust, run Developer: Reload Window.

The first load is slow in a very large repository

Mergeline draws only the rows on screen and loads history in batches, so scrolling should stay smooth even at 100,000 commits. The first batch is the part you wait for. Things that help, in order:

  • Load fewer commits first. Set mergeline.initialCommits lower in your settings. The default is 500 and the minimum is 50. More commits load as you scroll, or when you click Load more. 
    // settings.json
"mergeline.initialCommits": 200
  • Hide what you do not need. Turn off remote-tracking branches with the remotes toggle in the toolbar (or "mergeline.showRemoteBranches": false), or use the branch filter to show one branch. Hiding stashes (mergeline.showStashes) and the uncommitted-changes row (mergeline.showUncommitted) also saves a little work; the uncommitted row needs a git status, which is slow in huge working trees.
  • Let git speed itself up. Git can keep a commit-graph file that makes history walks much faster. Write one now, and have git keep it current on every fetch: 
    git commit-graph write --reachable
git config fetch.writeCommitGraph true
    Or run git maintenance start once, which schedules this and other background upkeep for the repository.
  • Prune old remote branches. git fetch --prune removes remote-tracking branches that were deleted on the server, which shortens the ref list Mergeline has to draw.

I cannot see the Mergeline button

The button in the Source Control title bar appears only when the git provider is active, which means the open folder (or a folder inside it) must be a git repository. If the title bar is crowded, the button may be inside the … overflow menu. The status-bar button can be turned off with mergeline.statusBarButton, so check that setting too. The command Mergeline: Show Commit Graph works either way.

The graph shows the wrong repository, or one is missing

Use the repository picker in Mergeline’s toolbar. It lists every workspace folder and the nested repositories VS Code’s git extension has found. If a nested repository is missing from VS Code’s own Source Control view too, check the editor’s git.repositoryScanMaxDepth and git.autoRepositoryDetection settings, or open that folder directly.

The graph looks out of date

Remote branches are only as fresh as your last fetch. Click Fetch in the toolbar, then Refresh. If you changed the repository from a terminal, Refresh (or the command Mergeline: Refresh Commit Graph) reloads it.

Interactive rebase opens an editor I do not want

Interactive rebase runs git rebase -i in the editor’s integrated terminal, so git opens its todo list in your configured git editor. To edit it in a VS Code tab instead, set:

git config --global core.editor "code --wait"

Use codium --wait or cursor --wait for those editors. Save and close the tab to let the rebase continue.

How to report a bug

  1. Update to the latest release and check that the problem still happens.
  2. Open a new issue and include:
    • the Mergeline version, your editor and its version (VS Code: Help → About), your operating system, and the output of git --version;
    • whether you are in a local, Remote SSH, WSL or container window;
    • what you did, what you expected, and what happened instead, with the exact error message;
    • any errors from Help → Toggle Developer Tools → Console;
    • for drawing problems, a screenshot and a rough description of the history (for example “octopus merge of four branches”). A small public repository that shows the problem is ideal.
  3. Remove private details first. Issues are public. Blur commit messages, author names, branch names and remote URLs you would not want published.

Please do not post security problems with exploit details in a public issue. Open an issue asking for a private contact channel instead, without the details.
