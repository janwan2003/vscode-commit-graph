Diff Jupyter notebooks between git commits in VS Code

A Jupyter notebook (.ipynb) is a JSON file: cells, their source, their outputs and a lot of metadata. git stores and compares it as text, so a one-word change in a cell comes out as a JSON diff mixed with changed execution counts and outputs. This page shows what git diff gives you, how nbdime makes it readable in a terminal, and how to compare a notebook between any two commits cell by cell in VS Code.

What git diff shows

Here one cell changed from sum() to mean() and was run again. Plain git diff shows the JSON:

git diff HEAD~1 HEAD -- sales.ipynb
@@ -10,7 +10,7 @@
   {
    "cell_type": "code",
-   "execution_count": 3,
+   "execution_count": 7,
    "id": "e5f6a7b8",
@@ -19,17 +19,17 @@
       "text/plain": [
        "        sales\n",
        "region       \n",
-       "north    1200\n",
-       "south     950"
+       "north     400\n",
+       "south     317"
       ]
      },
-     "execution_count": 3,
+     "execution_count": 7,
      "metadata": {},
      "output_type": "execute_result"
     }
    ],
    "source": [
-    "df.groupby('region').sum()"
+    "df.groupby('region').mean()"
    ]

The code change is the last two lines. With images in the outputs (plots are stored as base64 text) or a few dozen cells, it gets much harder to find. Some teams strip outputs before committing, for example with nbstripout, which makes the diffs smaller but means the repository no longer has the results.

nbdime in a terminal

nbdime is the Jupyter project’s tool for diffing and merging notebooks (pip install nbdime). Its nbdiff takes two notebook files, or two git revisions and a path:

nbdiff HEAD~1 HEAD sales.ipynb
## replaced /cells/1/execution_count:
-  3
+  7

## modified /cells/1/outputs/0/data/text/plain:
@@ -1,4 +1,4 @@
         sales
 region
-north    1200
-south     950
+north     400
+south     317

## replaced /cells/1/outputs/0/execution_count:
-  3
+  7

## modified /cells/1/source:
-  df.groupby('region').sum()
+  df.groupby('region').mean()
  • -O (--ignore-outputs) leaves outputs out, so only source and metadata changes remain. Matching options leave out sources (-S), attachments (-A), metadata (-M) or cell ids (-I).
  • nbdiff-web takes the same arguments and shows the diff in your browser, with the cells rendered.
  • nbdime config-git --enable registers nbdime as git’s diff driver (and merge driver) for *.ipynb in the current repository, so plain git diff prints the nbdime format. Add --global to do it for every repository, and --disable to undo it.

We ran these with nbdime 4.0.4 and git 2.53.

VS Code’s notebook diff editor

VS Code opens .ipynb files as notebooks with its built-in Jupyter notebook support, and it has a notebook diff editor to match: the two versions side by side, cell by cell, with changed cells marked and the text inside each cell diffed. Its title bar has buttons to show or hide differences in outputs and in metadata (settings notebook.diff.ignoreOutputs and notebook.diff.ignoreMetadata) and Open Text Diff Editor for the raw JSON. (We checked these in VS Code 1.147.)

The built-in Source Control view uses it: click a changed notebook under Changes to see your uncommitted changes in it. What it does not give you is a notebook from an arbitrary older commit or a comparison of two commits.

The Git Graph extension’s View Diff opens the raw JSON text of a notebook instead. That is Git Graph issue #598, “View Diff should open VS Code’s rich diff viewer for Jupyter Notebooks”, opened in December 2021. When we checked on 20 November 2026 it was still open, with 17 thumbs-up.

Notebooks from any commit in Mergeline

Mergeline is a free, MIT-licensed git graph for VS Code, Cursor and VSCodium. From version 0.19 it opens .ipynb files in VS Code’s notebook diff editor wherever it shows a diff:

  • One commit: click the commit, then the notebook in the details pane. You see the notebook before and after that commit.
  • Two commits: click one commit and Ctrl-click (Cmd-click on macOS) another, then click the notebook in the list of files that differ.
  • A commit and your working copy: right-click a commit and choose Compare with working tree.

How it works: Mergeline serves each file revision through a read-only file system, so VS Code reads the file’s bytes at that commit the same way it reads a file on disk, and picks the editor it would use for that file type. The revisions are read-only; to change the notebook, open your working copy.

Images too

The same change applies to pictures. A PNG, JPG, GIF, SVG or other image at a revision now opens in VS Code’s image preview instead of as garbled text. In VS Code 1.147 the image preview handles jpg, jpe, jpeg, png, bmp, gif, ico, webp, avif and svg.

In a terminal, git diff only says Binary files a/logo.png and b/logo.png differ. To look at an old version, write it to a file: git show HEAD~1:logo.png > logo-old.png.

FAQ

Do I need the Jupyter extension to see a notebook diff?

Not to view one in VS Code: opening and diffing .ipynb files uses the notebook support built into VS Code. You need the Jupyter extension to run cells.

Can I hide output changes?

Yes. In the notebook diff editor, use the title-bar button to hide output differences, or set notebook.diff.ignoreOutputs to true. In a terminal, use nbdiff -O.

How do I see the JSON instead?

Click Open Text Diff Editor in the notebook diff editor’s title bar, or run git diff without nbdime’s driver.
