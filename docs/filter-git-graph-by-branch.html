Show only some branches in a git graph

A graph of every branch is useful for about a week. After that, old feature branches, release branches and a dozen remote branches make it too wide to read. Usually you care about two or three of them: main and the branch you are working on, or everything under feature/. Git can draw just those. This guide shows how with git log, and how to do the same in VS Code.

Name the branches you want

git log with no branch shows the history of the branch you are on. Give it branch names and it shows the history of those branches together, joined where they share commits:

git log --graph --oneline main feature/a
*   c7a5063 (HEAD -> main, origin/main) Merge feature/b
|\
| * 4ef1585 (origin/feature/b, feature/b) b1
* | d882386 three
|/
| * 0d810e7 (origin/feature/a, feature/a) a2
| * 2d3f8f2 a1
|/
* a980ab8 two
* 433d70d base

Any other branch that is not part of that history is simply not drawn. Here feature/b still appears because it was merged into main. You can name as many branches as you like, and tags or commit hashes work too. In a terminal the branch names in brackets appear by default; add --decorate if your output does not show them. For how to read the lines, see the git log --graph reference.

All branches, remotes, or a pattern

  • --branches starts from every local branch. --remotes starts from every remote-tracking branch, like origin/main. --all adds tags, stashes and everything else.
  • Both take a pattern. --branches='feature/*' shows every local branch under feature/; --remotes='origin/feature/*' does the same for the remote ones. Quote the pattern so your shell does not expand the *.
  • Combine them: git log --graph --oneline main --branches='feature/*' shows main plus all feature branches.
  • To leave some branches out of a pattern, put --exclude before it: git log --oneline --exclude='feature/old*' --branches. We checked: placed after --branches, it has no effect.
git log --graph --oneline --branches='feature/*'
* 0d810e7 (origin/feature/a, feature/a) a2
* 2d3f8f2 a1
| * 4ef1585 (origin/feature/b, feature/b) b1
|/
* a980ab8 two
* 433d70d base

Remote-tracking branches only move when you fetch. Run git fetch --prune first, or the graph shows the remote as it was last time.

Leave out what is already on main

Often the question is not “show me this branch” but “show me what this branch adds”. A ^ in front of a branch name hides every commit reachable from it:

git log --oneline feature/a ^main
git log --oneline main..feature/a      # the same thing, shorter
0d810e7 a2
2d3f8f2 a1

Both list only the commits on feature/a that are not on main. The ^ form lets you combine more: git log --graph --oneline --branches ^main shows every local branch’s unmerged work and nothing else. The compare guide explains two dots and three dots.

Make a busy branch simpler

--first-parent follows only the first parent of each merge. On main that means the merges and the commits made directly on it, without the commits inside each merged branch:

git log --graph --oneline --first-parent main
* c7a5063 (HEAD -> main, origin/main) Merge feature/b
* d882386 three
* a980ab8 two
* 433d70d base

--simplify-by-decoration keeps only commits that a branch or tag points to, plus a few git needs to keep the graph connected. It turns a long history into a map of where branches are:

git log --graph --oneline --simplify-by-decoration --branches
* 0d810e7 (origin/feature/a, feature/a) a2
| * c7a5063 (HEAD -> main, origin/main) Merge feature/b
| * 4ef1585 (origin/feature/b, feature/b) b1
|/
* 433d70d base

In VS Code’s built-in graph

The graph in VS Code’s Source Control view has a branch picker in its title bar. In VS Code 1.147 it offers Auto, the current branch together with its remote branch and the branch VS Code considers its base; All, every branch; or a list where you tick one or more branches, tags or remote branches to show. (We read these labels from the strings shipped with VS Code 1.147.) It is a good quick filter. It has no equivalent of ^main, --first-parent or a name pattern; for those, use the terminal. For a wider comparison of the built-in graph and extensions, see seeing a branch graph in VS Code.

Do it in Mergeline

Mergeline is a free, MIT-licensed git graph for VS Code. By default it shows all branches, tags and remote branches. From version 0.8 you can narrow that to any set of branches.

  1. Open the Branches dropdown in the toolbar. It is a checklist of your local and remote branches. Tick any number of them and the graph shows only their history: every commit reachable from at least one ticked branch, like git log main feature/a.
  2. Current branch ticks just the branch you have checked out. All branches clears the selection and shows everything again.
  3. Hide remote branches with the Remote branches checkbox in the toolbar. That is the graphical version of leaving out --remotes.
  4. Or keep everything and dim the rest (new in 0.8). Turn on the setting mergeline.dimOtherCommits. Commits that are not reachable from HEAD are then drawn faded, so your branch’s line stands out while the other branches stay in view.

To narrow the graph to one person’s commits instead, or to keep dependabot/* branches out of it for good, see git log by author.

Everything else works on the filtered graph as usual: click a commit for its changes, or right-click it to cherry-pick, merge or compare. The git log --graph reference lists the git options Mergeline uses.
