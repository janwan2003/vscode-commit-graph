Delete multiple local git branches at once

After a few months every repository collects local branches whose pull requests were merged long ago. git branch -d takes several names, but you still have to find the right ones and keep main out of the list. This page shows how to list merged branches and branches deleted on the remote, delete them in one command without losing work, get one back if you were wrong, and do the same from a list with check boxes in VS Code.

Delete every merged branch

git branch --merged main lists the local branches whose tip is already part of main: every commit on them is reachable from main, so deleting the branch name loses nothing. Without a branch name it compares with HEAD, the branch you are on.

git branch --merged main
  develop
  done1
  done2
  gone1
* main

The list always includes main itself, marked with * when it is checked out, and it can include long-lived branches that happen to point at an older main commit, like develop here. Leave those out, and use --format so the output is plain names without the * or + markers:

# look first
git branch --merged main --format='%(refname:short)' | grep -vxE 'main|master|develop'
done1
done2
gone1
# then delete
git branch --merged main --format='%(refname:short)' | grep -vxE 'main|master|develop' | xargs -r git branch -d
Deleted branch done1 (was 51c11c6).
Deleted branch done2 (was cc61ea5).
Deleted branch gone1 (was 09e87da).
  • grep -vx drops lines that match the whole pattern, so main goes but main-fix stays. Add any other branch you keep to the pattern.
  • xargs -r does not run git branch -d at all when nothing is left. That is GNU xargs; if yours rejects -r (older macOS), leave it out, since BSD xargs already skips empty input.
  • Run it while you are on main: for a branch without an upstream, -d checks against the branch you are on, not the one you gave --merged.
  • git will not delete the branch you have checked out, or one checked out in another worktree (error: cannot delete branch 'x' used by worktree at '…'). The other names are still deleted.
  • Only local branches are deleted. The branches on the server stay; delete one there with git push origin --delete name.

We ran every command on this page with git 2.53 in a scratch repository.

-d or -D

git branch -d deletes a branch only if it is merged: into its upstream branch if it has one, otherwise into HEAD. If not, it stops with

error: the branch 'wip' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D wip'

and moves on to the next name. That makes -d safe to feed a long list: the worst case is that it refuses some names. git branch -D (short for --delete --force) deletes whatever you give it, including commits that exist nowhere else. Before using it, look at what would go:

git log --oneline main..wip     # commits on wip that main does not have

Because -d checks the upstream first, it can refuse a branch that --merged main listed, if the branch has commits its upstream does not have. We saw warning: not deleting branch 'x' that is not yet merged to 'refs/remotes/origin/x', even though it is merged to HEAD. Push it first, or use -D once you have checked.

Branches deleted on the remote

When a pull request is merged, GitHub, GitLab and Bitbucket can delete its branch on the server. Your local branch still tracks it. After git fetch --prune, which removes the remote-tracking branches that no longer exist, git marks those local branches as gone:

git fetch --prune
 - [deleted]         (none)     -> origin/gone1
 - [deleted]         (none)     -> origin/wip
git for-each-ref --format='%(refname:short) %(upstream:track)' refs/heads
develop
done1
done2
gone1 [gone]
main
wip [gone]

git branch -vv shows the same thing for people rather than scripts: wip f97b21b [origin/wip: gone] wip.

To delete them, keep the names with [gone] and pass them to git branch -d:

git for-each-ref --format='%(refname:short) %(upstream:track)' refs/heads | awk '$2 == "[gone]" {print $1}' | xargs -r git branch -d
Deleted branch gone1 (was 09e87da).
error: the branch 'wip' is not fully merged
hint: If you are sure you want to delete it, run 'git branch -D wip'

With the upstream gone, -d compares with HEAD, so run it from main after pulling. A branch it refuses either has commits you never pushed, or was squash-merged (next section). The ahead/behind guide has more on [gone] upstreams, and manage git remotes covers pruning, including git config --global fetch.prune true to prune on every fetch.

Squash-merged branches

If your team squash-merges or rebase-merges pull requests, the commits on main are new commits with different hashes. git cannot see that your branch’s commits are in there, so the branch never shows up in --merged, and -d refuses it. The [gone] marker is the useful signal then: the server deleted the branch after merging it. Check git log --oneline main..branch, compare with what was merged, and use -D for that branch.

Get a deleted branch back

Deleting a branch removes only its name, not its commits. Every delete prints the commit the branch pointed at:

git branch -D wip
Deleted branch wip (was f97b21b).
git branch wip f97b21b     # back, at the same commit

The deleted branch’s own reflog and its upstream setting (branch.wip.remote and branch.wip.merge) go with it, so set the upstream again with git branch -u origin/wip wip if the remote branch still exists. If you no longer have the hash, look for the branch name in git reflog, which lists the commits HEAD has been on. Commits that no branch, tag or reflog entry points at are removed by git gc after a grace period (two weeks by default, setting gc.pruneExpire), so do not leave it for months. More in the undo guide.

In VS Code

VS Code’s built-in Git: Delete Branch… command shows a list of branches and deletes the one you pick, asking before it forces an unmerged one. The Source Control Graph can delete a branch from its label. Both delete one branch at a time.

Delete several branches in Mergeline

Mergeline is a free, MIT-licensed git graph for VS Code, Cursor and VSCodium. From version 0.19 it can delete many local branches from one list.

  1. Open the list. Right-click any local branch badge in the graph and choose Delete several branches…, or run Mergeline: Delete Branches… from the Command Palette. The branch you right-clicked is already ticked.
  2. Tick the branches. All local branches are listed, with the ones merged into your current branch and the ones deleted on the remote first. Each has a note, such as merged into main · origin/feature-x deleted on the remote or not merged into main · tracks origin/wip. The branch you have checked out and branches open in other worktrees are not offered, because git refuses to delete them.
  3. Confirm. If every branch you picked is merged, Mergeline asks once and deletes them. It has already checked that each one is merged into your current branch, so it also deletes a merged branch that -d would refuse because its upstream is behind. If some are not merged, the dialog names them and offers Delete all N, which uses git branch -D for the unmerged ones, or Delete the K merged, which keeps them.
  4. Undo. The notification afterwards has an Undo button. It recreates each deleted branch at the commit it pointed at and restores its upstream setting.

Only local branches are deleted. To delete a branch on the server, right-click the remote branch badge (for example origin/feature-x) and choose Delete on remote…; that asks first.

Deleting several branches at once is Git Graph’s feature request #184, “Delete multiple branches at once”, opened in September 2019. When we checked on 20 November 2026 it was still open, with 6 thumbs-up.

FAQ

Does git branch -d delete the branch on GitHub?

No. It deletes the local branch name only. The remote branch is deleted with git push origin --delete name, or on the hosting site.

Why does --merged not list a branch I know was merged?

It was probably squash-merged or rebase-merged, so its commits reached main under new hashes. Or your local main is behind: pull first, or compare with origin/main after a fetch (git branch --merged origin/main).

Is there a git command that deletes all merged branches?

Not as one built-in command. The pipe above is the usual way; some people save it as an alias. Look at the list without the last step before you run it the first time.
