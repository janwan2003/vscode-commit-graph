Git Graph right-click menu not working in VS Code? Causes and fixes

You right-click a commit or a branch in the Git Graph extension and nothing useful happens: no menu at all, or only the editor’s plain Cut / Copy / Paste menu instead of checkout, merge, cherry-pick and the rest. This page explains the known case from 2025, gives a checklist for finding the cause on your machine, and, if you would rather move on, describes a maintained alternative.

Mergeline is an independent project. It is not affiliated with or endorsed by Git Graph or its author. “Git Graph” here refers to the extension by mhutchie.

The known 2025 issue: a VS Code regression

In February 2025 many people saw the menu disappear at the same time, right after a VS Code update. The Git Graph issue #870, “Context right-click menu disappeared with last vscode update”, collected 357 thumbs-up. The cause turned out to be on VS Code’s side: commenters linked VS Code issue #239862, “Native context menu hijacks custom one in webview editor”, which VS Code fixed in its January 2025 Recovery 2 release (1.97.2). Users in #870 confirmed the menu came back after updating, and the issue was closed on 18 February 2025.

So if you are on an older VS Code, updating is the first thing to try. If you are on a current version and the menu is still missing, the cause is something else, and the checklist below will help narrow it down.

Issue details checked on 20 November 2026.

In VSCodium

A separate report, #863, “Context menu not available in VSCodium”, was opened in January 2025. In it, a commenter reported still seeing only Cut/Copy/Paste in VSCodium 1.97.2 after VS Code itself was fixed, and the issue was reopened in April 2025. It was still open on 20 November 2026. If you use VSCodium, update it first, then work through the same checklist. For more on extensions in VS Code forks, see git graph in Cursor and VSCodium.

Checklist: things to try

Work through these in order. Each step either fixes the problem or rules out a cause.

1. Update the editor

Check your version with Help → About, then use Help → Check for Updates (on Linux, update through the package manager you installed it with). Menus inside extensions are drawn in a webview, so they depend on the editor’s webview and Electron versions, as the 2025 regression showed.

2. Reload the window

Run Developer: Reload Window from the Command Palette (Ctrl/Cmd+Shift+P). This restarts every extension and webview without closing your files, and clears up a surprising number of one-off glitches, especially after an extension or editor update.

3. Check the workspace is trusted

If the window shows a Restricted Mode banner, VS Code is limiting what extensions can do in this folder. It disables extensions that do not declare support for untrusted workspaces, and that includes its own built-in Git features. Git Graph 1.30.0 was released before Workspace Trust existed and its manifest declares no such support. Run Workspaces: Manage Workspace Trust and trust the folder if you trust its contents.

4. Rule out other extensions

Another extension or a setting can interfere with menus or webviews. The quickest test is a clean profile: Profiles: New Profile…, create an empty one, install only Git Graph in it, and open the same folder. If the menu works there, something in your main profile is the cause. To find which extension, run Help: Start Extension Bisect in your main profile: it disables half of your extensions at a time and asks whether the problem is still there, until it narrows it down to one.

5. Check that git is found

Open the integrated terminal and run:

git --version

If that fails, install git or add it to your PATH, then restart the editor. Git Graph also honours VS Code’s git.path setting, so if you set that, make sure it points at a working git executable. A git problem usually breaks the whole graph rather than only the menu, but it is a quick thing to rule out.

6. Look for errors in the developer tools

Run Developer: Toggle Developer Tools and open the Console tab. Clear it, right-click in the graph, and see whether any red errors appear. Developer: Open Webview Developer Tools shows the console of the webview itself, which is where an extension’s own menu code runs. You may not be able to fix what you find, but the exact error text is the most useful thing you can put in a bug report.

If nothing helps

Search the Git Graph issue tracker for your symptom before opening a new issue, and add a thumbs-up rather than a “same here” comment. If you do open one, include the output of Help → About, your operating system, the Git Graph version, and any console errors from step 6.

Be aware that the latest Git Graph release is 1.30.0, from 5 April 2021, so a fix on the extension’s side would need a new official release. Its licence does not permit publishing derivative works, so no one else can legally publish a patched, maintained fork. (That is a plain-language summary, not legal advice. The Git Graph alternative page explains it in more detail.)

A maintained alternative: Mergeline

Mergeline is a free, MIT-licensed git graph for VS Code, VSCodium, Cursor and Windsurf, and it is actively developed. It has the same kind of right-click actions:

  • Commits: create a branch or tag, check out, cherry-pick, revert, merge, rebase onto it, interactive rebase in a terminal, reset (soft, mixed or hard), compare with the working tree, copy the hash or subject.
  • Branches: check out, merge, rebase, compare, push, pull, rename, delete (locally or on the remote).
  • Tags and stashes: push or delete tags; apply, pop, drop or branch from a stash.
  • Since 0.6: on commits of your current branch, Edit commit message…, Move commit up / down (0.7), Squash into parent and Drop commit…, each with a one-click Undo. New in 0.7: a bar above the graph for a rebase or merge stopped on conflicts, with Continue, Skip and Abort.

Its menus are drawn inside its own webview too, so an editor regression like the 2025 one could affect it as well. The difference is that it is actively maintained: if something breaks in a new editor version, a fix can ship in the next release, and because it is MIT-licensed, anyone may fork and publish it.

  1. Install the .vsix from the latest release with Extensions: Install from VSIX…. It can sit alongside Git Graph: its commands and settings all start with mergeline.
  2. Open the graph with the Mergeline button in the Source Control title bar, or run Mergeline: Show Commit Graph.
  3. Right-click a commit, branch badge, tag or stash. If a menu ever fails to appear, please open an issue with your editor version.
